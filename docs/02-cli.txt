CLI 设计（命令 / 参数 / 输出契约）
================================================================

设计原则
  1. 命令少而正交：list 选、describe 读、sample 起手、gen 出活、doctor 修。
  2. 一切给 AI 看的信息都走 stdout 的结构化输出（--json），人看的走中文表格。
  3. 所有可预期失败都带"为什么 + 怎么办"，不打印堆栈（--verbose 才打）。

命令

  paper list [--json]
      无参数：模板清单（id / 名称 / 格式 / useWhen / 组件 id 列表）
      带 id ：该模板的组件清单，附带"可选组件什么时候自动出现"

  paper describe <模板 id> [--json]
      模板定位、数据契约（逐字段类型+必填+说明）、组件、示例数据、常用命令
      --json 时额外给出完整 schema 对象，便于程序化填数据

  paper sample <模板 id> [-o data.json] [--json]
      输出示例数据（模板手写的 sample，缺省时由 schema 的 example 兜底推导）

  paper gen <模板 id> -d data.json [-o out.<ext>] [--json] [--open]
      [-c <组件 id>]... [--set k=v]...
      1) 读数据 -> 2) schema 校验 -> 3) 选组件 -> 4) 渲染 -> 5) 落盘

  paper doctor [--json]
      bun 版本 / 模板与示例数据自洽 / 组件 id 重复检查 / 字体来源 /
      pdf 最小文档能否生成 / skill 是否安装

参数
  -d --data        数据文件（必填）。缺文件、JSON 语法错、字段不符都会明确指出
  -o --out         输出路径，缺省 <模板 id>.<格式>；目录不存在会自动建
  -c --component   显式指定组件，可重复或逗号分隔；给错 id 会提示正确 id 列表
     --set k=v     透传给模板的自定义参数（ctx.params）
     --json        机器可读输出
     --open        macOS 下用系统程序打开产物
     --verbose     打印堆栈
     --quiet       不打印过程
     --no-color    关闭 ANSI 颜色

数据流

    data.json ──► validateData(schema) ──┬─ errors   ──► 逐条报错 + 退出码 1
                                         └─ warnings ──► 提示"字段会被忽略"
        │
        ▼
    selectComponents(template, data, --component)
        │  规则：显式 -c > 非可选组件 > optional 且 when(data) 命中
        ▼
    renderTemplate(ctx) ──► Artifact ──► materialize() ──► 写文件
        │                     (docx Document / pdf builder / html string)
        └── ctx.use(id) 逐个渲染组件；docx 收块数组，pdf 直接画，html 收字符串

输出契约（--json）

  成功：
    { "ok": true, "template": "...", "format": "pdf", "out": "/abs/out.pdf",
      "bytes": 517619, "components": ["cover","summary"], "dataFile": "/abs/data.json" }

  失败：
    { "ok": false, "error": "数据校验失败 ..." }   // 退出码 1

  其他命令：list 返回 {templates:[...]} 或 {id, components:[...]}；
  describe 返回 {id, schema, components, sample, commands}；
  doctor 返回 {ok, checks:[{name,status:ok|warn|fail,detail}]}。

错误与提示示例

    ✗ 数据校验失败 metrics[0].value：缺少必填字段（本周数值，带单位，例如「22.1%」）
      提示：参考 paper describe prd-html 的字段说明，或 paper sample prd-html 重新生成示例

  常见错误码（core/errors.ts）
    E_USAGE    参数用错（拼错子命令、漏 -d）
    E_NOT_FOUND 模板/组件/文件不存在
    E_DATA     JSON 语法错、数据不符合 schema
    E_ENV      缺字体等环境问题
    E_RENDER   渲染阶段异常
    E_IO       读写失败

退出码
  0 成功；1 任何失败（包括 doctor 检测到 fail 项）。
