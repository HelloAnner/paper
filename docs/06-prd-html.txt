PRD（HTML）模板：设计复刻与数据契约
================================================================

目标
  把一份"设计过的" HTML 需求文档（悟帆 PRD 风格）变成 paper 的 html 模板：
  同一份 data.json + 同一套 CSS，产出与原始文档一致的排版。

  只做 html。docx / pdf 是各自独立的模块，不复用这里的任何代码。

原始文档长什么样
  · 版心 1120px 白纸，浅灰背景，1px 描边，72px 左右留白
  · 顶部 masthead：3px 黑线 + 全大写小字（悟帆 / 产品需求文档）
  · 标题区：h1(36px) → 绿色副标题(24px) → 灰色元信息(13px) + 细线
  · 阅读目录：只列 h2，两种排布——
      inline：一行行内绿链接（原设计，适合短标题，如「背景」「一、看现状」）
      list  ：两列编号竖排（01/02…，适合长标题，一屏内可扫读）
      auto（缺省）：最长标题超过 10 个字、或条目超过 8 条时自动用 list
  · h2(28px，上方 2px 黑线) / h3(22px) / h4(18px)
  · 正文 16px/1.85；行内可加粗、行内代码、绿色强调
  · 表格：表头浅绿底 + 上下描边，斑马纹，单元格可含有序列表 / 分组标题 / 状态圆标
  · 图：内联 SVG（自带宽高、含 <text>），下方右对齐 11px 图注
  · 底部 footer：2px 黑线 + 小字
  · 打印：A4 / 16mm 页边距 / h2 分页 / 图注隐藏 / 表格 8.2pt

设计令牌
  --ink    #202c27   正文
  --muted  #69746d   次要文字
  --line   #dce2dc   描边
  --green  #247356   强调
  表头底 #edf2ed   斑马纹 #fbfcfa   单元格描边 #dce2dc   表头描边 #bacabf
  状态色：支持 #247356 / 不支持 #b74440 / 不适用 #748079

数据结构（data.json）

  {
    "masthead": "悟帆 / 产品需求文档",        // 顶部小字，可省
    "title": "悟帆 × 简道云能力套件升级",      // 必填
    "tagline": "让 AI 员工走进业务现场",       // h1 下方绿色副标题
    "meta": "产品需求文档 · V1.0 · 方案评审稿", // 再下方灰色说明
    "tocLabel": "阅读目录",                    // 目录标题，不填不出目录
    "tocStyle": "auto",                       // 目录排布：auto（缺省）/ inline / list，见下
    "toc": ["背景", "一、看现状"],             // 可选：手写目录；不写则自动收集全部 h2
    "footer": "悟帆 · 产品需求文档",            // 文档底部落款
    "blocks": [ ... ]                          // 正文，按顺序渲染
  }

块（blocks[]）—— 顺序即版面顺序

  { "type": "h2", "text": "背景" }
  { "type": "h3", "text": "1.1 客户场景：具体卡在哪一步" }
  { "type": "h4", "text": "4.1.1 业务应用面板与三个功能入口" }
  { "type": "p", "text": "正文。支持 **粗体**、\`行内代码\`、==绿色强调==。" }
  { "type": "list", "ordered": true, "items": ["第一条", "第二条"] }
  { "type": "quote", "text": "需要特别提醒的一段话（绿色竖线引用块）" }
  { "type": "table", "widths": [21, 79], "head": ["核心判断", "事实与局限"],
    "rows": [ [ 单元格, 单元格 ], ... ], "variant": "plain" }
  { "type": "figure", "src": "figures/01-usage.svg", "caption": "PNG 画幅 · SVG 源图" }

  说明：
  · h2/h3/h4 的锚点由模板按出现顺序生成（section-1、section-2…），目录自动指向它们；
    也可以在块上写 "id" 覆盖。
  · 内联语法只有三种：**粗体** / \`行内代码\` / ==绿色强调==（原 .can-do）。
  · list 默认无序，ordered: true 为有序。

单元格（table.rows 里的元素）—— 三种形态

  1. 字符串（最常见）：支持内联语法
       "写入字符串，保留换行。"

  2. 状态圆标：{ "status": "yes" | "no" | "na", "text": "支持" }
       yes → 绿底白 ✓ ；no → 红底白 ✕ ；na → 浅底灰 —

  3. 块数组（一个单元格里放多段/多组内容）：
       [
         { "status": "yes", "text": "支持" },              // 数组里也能放状态圆标
         { "type": "text", "text": "需明确目标成员" },        // 独立成行的一段文字（不带段间距）
         { "type": "p", "text": "第一段" },
         { "type": "list", "ordered": true, "items": ["a", "b"] },
         { "type": "group", "title": "小标题（分组标题）", "blocks": [ ...同上... ] }
       ]

  group 用于原文档里的 .cell-group（分组标题 + 组内列表/段落，组间有分隔线）。

行也可以写成对象形态（用于表内分组分隔线）：

  { "cells": ["附件", { "status": "no", "text": "不支持" }], "groupStart": true }

  groupStart 会给这一行加 2px 上边框，用于 field-support-table 这类"分组小标题"表格。

表格 variant（决定列宽与细节样式；宽度也可以直接用 widths 覆盖）

  plain              默认（首列 21%）
  capability-table   功能清单与设计索引（16/35/12/19/18）
  field-support-table 字段支持矩阵（15/20/16/49，首列加粗、组间双线）
  goals-table        设计目标（10/27/63，首列绿色大字）
  acceptance-table   验收表（24/33/43，首列加粗变绿）
  acceptance-tools-table   （27/12/27/34）
  acceptance-fields-table  （20/35/45）
  acceptance-skill-table   （32/20/48）
  acceptance-index-table   （28/56/16）

图（figure）

  src 指向 .svg 文件（相对 data.json 所在目录），模板把 SVG **内联**进 HTML
  （保持单文件自包含，和原文档一致），并加 <figure> 描边 + 右对齐图注。

已知取舍（复刻原文档时确认过）
  · 原文档另有一个固定定位的悬浮目录（JS 交互 + 滚动高亮），模板不复制它：
    静态文档保留正文里的"阅读目录"即可，悬浮目录属于网页交互，不属于文档。
  · 原文档正文里有 3 处把状态圆标写在段落中间（不是表格里），迁移时被拉平成
    普通文字；表格里的 92 个圆标全部保留。
  · 原文档表格中的"组间双线"用行的 groupStart 标记保留（3 处）。
  · 复刻验收结论：31 张图与原文 SVG 字节一致；57 张表、488 行、1277 个单元格、
    23 个单元格分组、8/17/35 个 h2/h3/h4 全部一致；正文文字除 2 处空格合并外一致；
    首屏截图与原文档像素一致。

模板组件（paper list 可见）

  masthead  必选  顶部横线 + 文档类别小字
  title     必选  标题区（h1 + 绿色副标题 + 灰色元信息）
  toc       可选  阅读目录（有 tocLabel 或 toc 时出现）
  prose     必选  标题 / 段落 / 列表 / 引用块
  tables    可选  blocks 里出现 table 时自动出现
  figures   可选  blocks 里出现 figure 时自动出现
  footer    可选  有 footer 字段时出现

  块的分发：模板遍历 blocks，按块类型找到负责的组件（h2/h3/h4/p/list/quote → prose，
  table → tables，figure → figures），调用 ctx.renderBlock(id, block)。
  这样既保持文档顺序，又能用 -c 只出某几类块。
